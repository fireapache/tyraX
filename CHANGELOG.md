# Changelog

What changed in each TyraX release, newest first. Every release is also on
[GitHub Releases](https://github.com/doctorspider42/tyraX/releases) with its
installers; releases before 1.170.0 are described only there and in the git
history.

## 2.1.0 - unreleased

- **A game built with a different `TYRA_SKIN_INDEXED` than the engine library fails to link (`SkelSkin::Indexed::checkBuild`).** The flag changes the VU1 packet layout and is read by headers on both sides; a mismatch used to build and then draw corrupt skinned bodies. The library now defines a symbol for its value and the generated game's start-up names the symbol of its own, so the build stops with an undefined `kBuildIndexedOn` / `kBuildIndexedOff`.
- **A skinned part drawn with a translucent colour keeps its triangle order (`reorderMesh`).** The locality reorder of the indexed skinned stream permutes the triangles of every part and level, which is invisible only where the draw order does not matter. A part whose material colour has alpha below 1 is now left in its authored order, so overlapping translucent triangles blend as authored.
- **The experimental skin arms are compiled out (`TYRA_SKIN_EXPERIMENTAL`, default 0).** The batch MMI kernel (`TYRA_SKIN_MMI_BATCH`), the MMI corner of the fixed-point blend (`TYRA_SKIN_FIXED_MMI`), and the vector / float-core stream path (`TYRA_SKIN_FIXED` 0) were measured slower than the shipped unique and indexed passes and were still in every build: their code, a batch block in every bind level, the MMI operands in every pose fold and a flag test per part. Nothing of them is built unless the flag is 1 (the host verifier of the MMI corner builds that way); the code is kept for review. The comments and docs that called the vector path the default now say it is experimental, and `skinPlainPart` makes the pose fold for the batch arm too (it called the fixed pass with no fold).
- **The skinning host checks run without a game checkout (`tools/make-skin-fixture.cpp`).** `tools/verify-tyrax2-host.py --only skel`, `skel-indexed`, `skel-fused` (and `all`) read a small skinned figure the new tool writes through the editor's own `.tskl` writer (nine bones, three parts with generated levels, one to four bones a vertex) instead of failing when a sibling game checkout is missing; `--tskl <model>` and `--glb <model>` still run them on any model. The text of the skinning docs, the verifiers and the changelog no longer names a particular game or model.
- **The render slot layout frees its sides through the allocator's own function and is charged to Skinning (`SkelRenderSlots::FreeFn`).** `reset` freed every side with `delete[]` whatever `AllocFn` made it, and `SkelSlot::make`, the slot lists and the slot table were taken in the caller's budget (the game's System budget, which halts when full) with throwing vector growth. `layout` now takes the matching `FreeFn`, runs under the Skinning scope and probes the lists and the table at their exact size first: a full budget carves fewer slots instead of halting. `docs/render-slots.md`; `tools/verify-skel-render-slots.cpp`.
- **A package the clip route could not expand is logged (`StaPipQBuffer::expandIndexed`).** An indexed package that crosses a frustum plane is decoded to plain corners into the copy pool; when the pool could not grow (a refusing Renderer budget) `pack` answered false and `expandIndexed` ignored it, leaving an empty package with no trace. It now raises a `[MEM] fallback` line once a second per stream, as the other render refusals do. `docs/memory-manager.md`.
- **A body reads which parts are textured from its look (`SkelInstance::create` `look`).** The constructor took the texture presence of each part from the shared `SkelModel`, whose paths are those of the first look loaded; when that look's texture failed to load the path was cleared from the model and a second look's textured part got no coordinates frame and so no texture bag. The game template passes the look it keeps for the model. `docs/animated-models.md`, "One model, several looks".
- **The animation frame counter advances every frame (`animLodTick`).** "Drawn last frame" (`animBonesNow`, the far tier's entering-view rule) compares a body's last tick with the counter, which advanced only when an animated body was in view: after frames with none, a body drawn long before still counted as drawn last frame. The counter now advances before the early return, once per frame (not per split-screen pass). `docs/animated-models.md`, "Drawn last frame".
- **The animated-model bake warns when a mesh's UVs do not fit the UV grid (`tmdl::uvSpanWarnings` over bare coordinates).** The static-model bake already named the mesh and part whose UVs span more than a 4-bit-fraction grid holds (2047 repeats, they saturate) or whose triangles span more than 16 repeats; a `.tskl` went through the same grid (`TmdlCompact::uvGrid`) silently. The bake now runs the same two checks over every part and level of a skinned model and reports them with the model, part and level. `tools/verify-tmdl.cpp`.
- **A body no render slot serves is drawn from streams of its own (`SkelInstance::slotRefused`, `releaseOwnStreams`).** The template skipped a slot body whose slot was missing or unwritten, so a model loaded after the layout (more parts than `partCapacity`, or more bytes at a tier than the slot has), a body whose bag layout differs from the level's shared indexed packaging, `bindSlot` failing, or every tier being full, left the body invisible for good. `bindSlot` now says when no slot will ever hold the body (`slotRefused()`), a refused packaging or a busy side is only a wait, and a slot body with no drawable slot takes the path of a body that never had one - own streams, at the model's cheapest level if the wanted level is refused - and gives them back when a slot serves it. The slots are not laid out again when a model is added (that frees and carves the memory the other bodies stand in). `docs/render-slots.md`, "A body no slot serves".
- **A render slot knows its model by a serial, not by its address (`SkelModel::serial`, `SkelSlot::boundModel`).** `bindSlot` skipped the re-placement when the slot's last model had the same address as the body's; a model freed and another loaded at the same address within one scene (layer streaming) was taken for the same one and its body skinned into streams placed for the other. Every `SkelModel` object, and every copy of one, now carries a serial that is never issued twice. `docs/render-slots.md`.
- **A body holds its model's bind cache (`SkelInstance::bindHold`).** `~SkelInstance` returns each pose buffer to its level's pool through raw pointers into the model's bind cache, which the residency pass frees together with the model; a body destroyed after its model read freed memory. The body now holds a `shared_ptr` to the cache, so the destructor's references stay valid. The game template frees models only after their bodies are gone, so no picture or timing changes. `docs/animated-models.md`, "What a body keeps of its model".
- **A model's bind data is built in stages that each ask the budget first (`buildBindCache`).** The first body of a model built the whole bind cache out of throwing containers in the refusing `Skinning` scope, guarded only by an estimate that took the unique level for at most a quarter of the corners; a flat-shaded model (uniques as many as corners) with the budget nearly full passed the estimate and halted the game inside the constructor. `SkelInstance::create` now builds the cache first, one stage at a time (reorder tables, skin source, unique level, the indexed packaging's object and ST payload), each asked for at its exact size from the nothrow `operator new[]`; a refusal answers null with the usual `[MEM] fallback` line and the caller asks again later. `SkelMesh::ordered` keeps a refused build from reordering a mesh twice. `docs/animated-models.md`, "Memory that is refused".
- **The indexed packaging and the pose buffer pool refuse instead of halting (`skel_room.hpp`, `PoseList`).** `Indexed::build`, `Shared::build`, the pose pool's lists and `retire()` used throwing containers inside the refusing `Skinning` scope, where a full budget halts the game on a throwing `new`; a flat-shaded model (as many unique vertices as corners, where the sizing estimate assumed a quarter) with the budget nearly full reached it. Each stage now asks for its exact size from the nothrow `operator new[]` first and the build answers false with `Shared::refused()` set; the pool's lists are reserved before a buffer is made so `retire` never allocates. `tools/verify-skel-refuse.cpp` (`--only skel-refuse`) counted 12 throwing requests over the limit before the change and 0 after. `docs/animated-models.md`, "Memory that is refused".
- **An indexed package fits the half of the double buffer the renderer fills (`Indexed::kHalfQw` 460).** `Indexed::fits` counted 461 quadwords for a half while the renderer's double buffer gives 460 (the last quadword is the other half's header) and `Shared::build` checked a second time against the smaller number. One constant now: a 75-corner package holds at most 74 uniques, a flat-shaded 75-corner package is refused by `Indexed::build` itself and the part takes 48-corner packages, as before. No stream changes. `docs/animated-models.md`, "Skinned streams with indexed corners".
- **The unique level keeps no skin source and no corner list (`SkelBindLod::uniq`).** Every row of the unique level is its own source, so the identity array is not stored (`skinBlendRange` reads an empty one as the identity), and the corner of each unique is made on the first plain-stream unique pass instead of at load: 61 to 53 bytes a unique, 8.8 KB for the soldier model. With the fused quantize the Skinning budget on the coop view is 1154 to 1128 KB used (peak 1164 to 1155), solo 1139 to 1112, stress 1122 to 1108. The rows stay float: the VU0 decode of a compact row matches the stored position for every unique but the normal (renormalised) for 1 of 1 162 and the weights for 327 of 1 162.
- **The indexed skin pass folds the stream parts' boxes with PMINH / PMAXH (`TYRA_SKIN_MMI_BOUNDS`, default 1).** The min and max of the quantized positions of the uniques in each stream part were six compares and six conditional stores for every (unique, part) pair; a part's three axes now live as four halfwords in one 64-bit value and a unique is folded into it with two lane ops. The values are the scalar loop's exactly (host check `--only skel-fused`; the first pass of the process compares the two over its real ranges, `SKINBOUNDS self-check`). With the fused quantize: coop work 18.28 to 17.99 ms, solo 11.90 to 11.76 ms, coop with every body re-posed 19.70 to 19.04 ms.
- **The indexed skin pass quantizes as it blends (`TYRA_SKIN_FUSED`, default 1; `skinEmitUniques`).** The pose box origin is the centre of the blended extent, so the pass blends each unique twice - once for the extent (VU0 `vmini` / `vmax`, nothing stored), once straight into the pose lanes - and no blended float is stored: the 32 bytes a unique of float scratch (24 064 bytes live) is made only for a plain-stream level or the fallback route. The VU0 sequence rounds half away from zero as `trunc(2x) - trunc(x)` and re-quantizes (`Unique::quantizeOne`) the few uniques whose lanes are within a few ulp of a tie or of the clamp, so its bytes are the earlier route's under either EE rounding (PCSX2 rounds the EE float ops to nearest, the VU0 truncates); the first pass of the process is checked against the earlier route (`SKINFUSED self-check`) and the route is dropped if they differ. Host check `tools/verify-tyrax2-host.py --only skel-fused`. Coop work 18.28 to 18.09 ms, solo 11.90 to 11.81 ms, coop with every body re-posed 19.70 to 19.28 ms.
- **A body makes its per-level stream pair when it first takes a stream of its own (`PartLod::streams`).** Every level of every part of every body held two `StaPipCompactStream` objects (about 300 bytes a level) whether or not the body ever drew from them; a body that draws render slots never does. The pair is now made by `ensureStreams` / `ensureIndexed`, so a slotted body keeps one null pointer a level. The soldier model match's Skinning falls by 54 KB (1 208 to 1 154 KB used on the co-op gym, 1 217 to 1 164 KB peak); streams, goldens and captures are unchanged. `docs/render-slots.md`, "What a body without a slot owns".
- **A model keeps no float copy of its bind pose (`SkelBindLod`).** The skinning bind data held, for every level of every part, a float position, normal, four weights, sorted joints and an influence count per corner (57 bytes a corner) for the life of the model, although the shipped passes read only the compact mesh and each level's unique set. A model now keeps the skin source (4 bytes a corner), the extent and the unique level, which is decoded straight from the compact mesh; the paths that blend every corner from float rows (the float VU0 skin with `TYRA_SKIN_INTO_STREAMS` 0, the vector stream path) make a level's rows when a body first needs them (`SkelInstance::ensureFloatLevel`, shared by the bodies of the model, refused like any Skinning buffer without losing a part). The soldier model's Skinning falls by 450 KB with the influence table (1 658 to 1 208 KB used on the co-op gym, 1 666 to 1 217 KB peak); streams, goldens and captures are unchanged. `docs/animated-models.md`, "No float copy of the bind pose".
- **The fixed-point pass makes a corner's influences when it blends it (`SkelBindLod::infl` removed).** The per-corner influence table (`Fixed::prepCorner`, 14 bytes a corner of every level of every part) was built with the bind data for the fixed-point and batch passes, which are off by default; the unique-vertex and indexed passes never read it. A pass that wants it computes it per unique corner from the same bytes, so streams are unchanged. Skinning memory: see `docs/animated-models.md`, "No float copy of the bind pose".
- **Readers of the skinning bind pose decode the compact mesh (`decodeVertex`).** `SkelInstance::vertexModel` and the bind-pose box of a body made without float arrays read each position from the `.tskl` mesh by `decodeMesh`'s arithmetic for one vertex (`decodeVertex`), instead of a float copy of the bind pose kept for the life of the model. The first step of retiring that copy; no memory change yet, results unchanged. `docs/animated-models.md`, "No float copy of the bind pose".
- **A game can read a body's bones at its current clip state, whatever the renderer's pose cadence (`ScriptContext::animBonesNow`, `SkelInstance::refreshBones`).** `boneWorld` / `animNodeModel` answer with the pose a body was last posed with, which the far tier (every 8th frame) and the animation LOD (every 2nd or 4th) leave up to 7 frames behind the clips; a game that seeded simulation state from it (a ragdoll started from the pose a fighter died in, whose chest then steers the medic who walks to it) computed something else with the far tier on. `animBonesNow(obj)` evaluates the skeleton only (no palette, no skin) and only when the matrices are behind, for a body a view drew in the last frame; the drawn pose and its schedule are untouched. A project that owns its `terrain_game.cpp` wires `scriptCtx.animBonesNow = &animBonesNowThunk;` by hand (`docs/animated-models.md`).
- **Render slot objects are sized to the parts the level uses (`SkelRenderSlots::layout` `partCapacity`, `SkelSlot::make`).** A `SkelSlot` held 8 streams a side (`kMaxSlotParts`) whatever its model's part count: 2 144 bytes each for the soldier model's two parts. The layout now takes the largest part count among the models the template loaded and each slot is one block of the object, the parts' offsets and `2 x partCapacity` streams, about 600 bytes for two parts; a body of more parts than its slot holds falls back to streams of its own. 88 KB less Level with the 58 slots of the CROSSINGS match (6 313 to 6 225 KB used on the co-op gym).
- **Bind data is built at its exact size.** The per-part unique level, the indexed packaging's gather list, the stream scatter's range list, the batch kernel's unique list and the merged meshes of the `.tskl` parse grew by `push_back` or by an insert after a copy and kept the unused part of the last doubling for the life of the model (a unique level had 192 592 bytes of capacity for about 105 000 in use). Each now counts first and reserves exactly that; the content is unchanged. The soldier model's Skinning drops by 52 KB (1 710 to 1 658 KB used on the co-op gym).
- **The looks of one model share one `SkelModel` (`SkelModel::geometryKey`, `SkelLook`).** A material override bakes its own `.tskl` (other texture names and colours, the same geometry), so a game with two teams' tints loaded the soldier model twice, with a bind cache each. `TsklLoader::parse` now stores a fingerprint of everything but the look (`geometryKey`) and `SkelLook::of` returns the look; the game template keeps one shared model for the files whose keys match (`sharesGeometryWith`) and a `look` per animated-model slot, so the helmet tints stay apart. The soldier model's two models cost 679 KB less Skinning and 236 KB less Level; `tools/verify-tskl-compact.cpp` checks that a repainted file shares and a moved vertex or changed clip does not.
- **A skinned far tier: a cheaper level posed every 8th frame (`farLod`).** A model with an authored `_LOD3` material (`kMaxAuthoredLod` 3) draws that level beyond its object's far LOD distance, as render-slot tier 3 (the cheapest; `Settings::renderSlotBytes[3]` reserves its slots, without it a far body takes the cheapest tier there is), and is posed only when `((tick + body) & 7) == 0`; a body entering a view is posed at once. The game template's `skelTierFor` and `skelRefreshDue` (the second built on the pose cadence) are checked by `tools/verify-skel-tier.cpp` (`verify-tyrax2-host.py --only skel-tier`), which extracts them from the template. The editor's *Distance and LOD* panel has **far LOD** beside mesh LOD (object JSON `"farLod"`, scene tables `ObjectData::farLod`; 0 = off, the default, and a model with no level 3 is unchanged). docs/animated-models.md "The far tier", docs/render-slots.md.

- **`.tskl` 4: animation clips are stored compact (`SkelClipCodec`).** Key times are whole ticks of the smallest of 24 / 25 / 30 / 48 / 50 / 60 / 120 / 1000 Hz that holds every key within 0.1 ms (a key authored as frame / fps comes back as the same float), channels with equal times share one time array, and a channel with one key - or a translation or scale that never changes - stores no times. Rotations were int16 already; translations and scales keep their floats, so a pose is the float sampler's bit for bit (the writer option `quantizeVectors` stores them as int16 in a box of the clip, half the size, within half a step). The soldier model's 13 clips fall from 100 800 to 70 138 bytes of tracks and its baked `.tskl` from 256 850 to 226 838. Version 1-3 files still load and are packed on load by the same rule the editor's writer uses; a clip whose keys fit no tick rate is stored at 1000 Hz with a warning, and a key beyond 65.535 s at 1000 Hz fails the bake. `python tools/verify-tyrax2-host.py --only anim`. See docs/animated-models.md, ".tskl version 4: compact clips".
- **Render slots: skinned vertex memory reserved per level of detail, held only by the bodies a view sees (`Settings::renderSlotBytes`).** A project that sets the bytes per tier in its memory registry gets slots carved from the `Skinning` budget at level load (`SkelRenderSlots::layout`, two stream sides a slot, sized for the largest model at the tier). Each view pass acquires a slot for each body in its frustum - a full tier gives the next cheaper one, a slot is held 30 frames after its last use, the second pass of a split screen acquires and skins the bodies only it sees - and a body that is drawn is skinned into its slot's spare side, then flips it. A body without a slot owns no skinned memory and, made with `SkelInstance::create(model, false)`, no per-body float mesh arrays (48 bytes a corner): the `Skinning` peak of the CROSSINGS coop and solo views falls from 6.1 / 5.9 MB to 2.4 MB (the pool, the bind data and the models' shared blocks), with the slots filled by the indexed pose buffer (`TYRA_SKIN_INDEXED`) or the plain compact stream (`StaPipCompactStream::allocateIn`). Zero bytes (the default) keep the per-body streams unchanged. `docs/render-slots.md`; `tools/verify-skel-render-slots.cpp` (`--only slots`).
- **A skinned stream that stores each unique vertex once (`TYRA_SKIN_INDEXED`, default 1).** With the flag (the default; 0 keeps the plain corner streams) a body skins each unique vertex once into a pose buffer (int16 / int8, one per part level, taken from a pool and retired when replaced) and VU1 assembles the triangles by index from the model's static corner table: the stream pair of the plain path (133 KB a LOD0 fighter, 34 KB at LOD2) becomes one pose buffer of 17.6 / 4.4 KB (13 %), the model's static blocks add 69 KB shared. The cull TD indexed image is a resident VU1 program (1 866 of 2 042 words; the billboard programs then use the on-demand set); a wholly visible bag replays two REFs a package with the entry and kick words captured into the static blocks, a package that crosses the frustum is decoded to plain corners for the clip path. On the soldier model the six skin gyms pass with the stream check reading the indexed stream, and the ten render captures differ from the plain path by at most 3/255 (PSNR 69.6 dB and up, SSIM 1.0000). Steady Skinning memory falls 0.6 MB on the coop, solo and stress views; the peak (the constructor's float mesh arrays) by 20 KB. The skin pass costs 50k COP0 ticks a part against 75k (stress view, first look). Paired against the flag off (same commit, two perf builds, runs interleaved): in normal play no frame time is measurable (stress view 14.60 ms of work against 14.60-14.61, solo 12.95 against 12.78-13.03, coop 18.8 against a flag-off spread of 18.0-19.7); with every body re-posed every frame it saves 1.16 ms on coop (5 %) and 1.70 ms on solo (9 %). See "Skinned streams with indexed corners" in docs/animated-models.md.

- **A batch integer skin kernel (`TYRA_SKIN_MMI_BATCH`, off) blends a pass's unique corners in inline asm.** `skel_batch.hpp`: aligned influence blocks, six MMI rows per block (immediate shifts from a forced fold), host lane model bit-equal to the integer definition on every soldier model part and LOD. On the device it is byte-equal to the scalar blend, but it does not yet meet the stress, coop or solo gates (stress 39.5 fps against 58.7; coop 29.4 ms against 20.5; solo 24.9 ms against 15.5). The fold and the final pass are the remaining cost. See "Batch skin kernel (host model)" in docs/animated-models.md.

- **Far bodies are re-posed on their turn (`TYRA_SKIN_CADENCE`).** A body beyond the animation-LOD distance is re-posed every 2nd frame, beyond twice it every 4th, staggered by index; a body with no held pose, not updated for more than four frames, or with a changed mesh LOD is re-posed at once. The rule is `SkelSkin::Cadence` (skel_cadence.hpp), checked by `tools/verify-skel-cadence.cpp`. In normal play the coop view reads 19.6 ms of work (23.37 ms with every body re-posed each frame) and the solo view 12.9 ms. See "Pose cadence of far bodies" in docs/animated-models.md.
- **The unique-corner skin is tuned for the merge (`TYRA_SKIN_UNIQUE_VU0`, on by default).** The unique path makes no per-pose fold; its normal is quantized without a renormalise; the stream loop keeps its tables in locals. On the coop view the work is 23.37 ms (BASE 20.47 ms) and the Skinning peak 6073 KB (BASE 6320 KB); see "Unique-vertex skin" in docs/animated-models.md for the measured table.
- **A skinned body blends its unique corners only (`TYRA_SKIN_UNIQUE_VU0`, on by default).** A part's corners that repeat an earlier corner's bind data are copied by the scatter, so only the unique corners (about 19 % of a fighter) are blended and quantized. The EE blends them with the VU0 corner loop on a per-level unique set built with the bind cache (`SkelBindLod::uniq`); `SkelSkin::writeUniqueStream` boxes, quantizes and scatters them into the int16 stream. `tools/verify-skel-unique.cpp` checks every part and LOD of the soldier model over 10 000 poses against the double-precision reference (positions within 0.51 steps, normals within 0.51 x127 units). See "Unique-vertex skin" in docs/animated-models.md.
- **The fixed-point skin has an MMI-model corner.** `SkelSkin::Fixed::cornerMmi` blends a corner in the EE's 128-bit lanes (PMADDH products, PMFHL.LW rows, word shifts, the joint sum as PMADDH over words), the lane model in `skel_skin_mmi.hpp`. It is bit-equal to the scalar blend over the synthetic part and every soldier model part and LOD (`tools/verify-skel-fixed.cpp`); on the EE the fixed blend can run the kernel (`TYRA_SKIN_FIXED_MMI`, off by default: measured slower than the scalar blend). The first pass per process checks it against the scalar blend (`SKINMMI` log line). See "Skinning in fixed point" in docs/animated-models.md.

- **A skinned body's compact stream is quantized on the VU0.** The stream path blends a re-posed body with the float VU0 corner loop into scratch and quantizes it with the batch quantizers, checked bit for bit against the scalar core on its first pass (`SkelSkin::gUseVector`). The stress view reads 47.7 fps against 60.0 fps for the float skin (paired, 2026-11-04) - still below it.
- **A skinned body skins straight into its compact stream.** `SkelInstance::skinInto` writes the spare side of each part's stream pair from the bind data (positions and normals quantized in a box per pose, centred on the pose's own extent), and the game template binds the drawn bag to the stream (`TYRA_SKIN_INTO_STREAMS`, default 1; set 0 for the float VU0 skin). The scalar skin core is the reference; the vector path quantizes the stream on the VU0. The stream path reads 47.7 fps on the stress view against 60.0 fps for the float VU0 skin - set 0 for the float skin on that view. Docs: `docs/animated-models.md`, "Skinning into compact streams".
- **A skinned body the memory budget cannot take keeps the level it holds.** When the Skinning budget refuses a level's stream, that level is not made: the body draws the cheapest level it already holds, and a refusal is logged once a second. Nothing halts.
- **A stream-bound animated body reports what it draws.** `ScriptContext::animLod` returned nothing for a body drawn from a stream, so the LOD gym passed with nothing checked. Its positions are now read from the stream.
- **`tools/verify-skel-compact.cpp` checks a real `.tskl`.** Given a `.tskl` path it decodes every part and LOD of the model and compares each corner with the float skin, in the model box (a stride error in the bind data fails it).

- **Render captures of every example, and a comparer.** `python tools/render-captures.py capture --out DIR` builds each project under `examples/`, boots it in a private PCSX2 with the software renderer and photographs its framebuffer at exact logic frames (100, 400 and 1000 by default), writing `DIR/<example>/<shot>.png` and a `manifest.json` with each example's status (`ok`, `crash`, `no-boot` or `timeout`), whether a second boot gave the same pictures, and a hash per shot. `compare BASE NEW --out DIR` then calls every shot identical, near (no pixel off by more than 4 levels), to review (with a diff and a side-by-side picture) or missing, prints a summary line and exits 1 only for a missing shot or an example that got worse. Capture before and after a change that touches rendering. See docs/render-captures.md.
- **A game can present every second field.** `setFieldsPerFrame(engine, 2)` in the generated runtime (`RendererCore::setFieldsPerFrame` underneath) shows a new picture every second vsync field - 30 fps in NTSC, 25 in PAL - and back to every field with 1, at any moment: a split screen can run at 30 while the rest of the game runs at 60. The frame clock follows it, so `g_frameDt` covers the two fields and a fixed-step game runs two steps a frame on NTSC and 2.4 on PAL - the same game speed and the same simulation, half as many pictures. A frame that is late still goes up at the next field. It works with two buffers and three (measured on PCSX2 with both, and across a display-mode switch that drops three buffers to two); with two it uses the vblank interrupt triple buffering uses, only while the setting is above 1, so a game that never calls it runs exactly as before. If that interrupt cannot be installed, or stops counting, the game falls back to every field until the next display-mode switch. See "Fields per frame" in docs/frame-pacing.md.
- A fixed-step game capped by *Catch up after a slow frame* no longer runs slow in PAL. The recipe for a game's own loop capped it at that many STEPS a frame, but a PAL field is 20 ms, 1.2 steps of a 1/60 s simulation, so one step a frame threw the rest away every frame and the game ran at 83 % of its speed with every frame on time. The runtime now publishes the cap in time (`g_frameDtMax`) and the step count it covers, rounded up (`frameStepCap(fixedDt)`), so PAL frames alternate one step and two and only a frame slower than the cap slows the game. The loop keeps the remainder of a frame shorter than a field too, so a game with *Disable VSync* no longer runs slow at the cap. The setting's choices now read in frames ("1 frame - slow down instead"), one field each unless the game presents every second field. See "Catching up after a slow frame" in docs/frame-pacing.md.
- A static model reaching its mesh LOD distance while memory is short no longer stops the game. Its reduced level is built the first time it is needed, while the game plays, and that build could only throw. The generated game now checks that the heap has room first; when it has not, the model keeps the level it shows and asks again the next frame. See "Mesh LOD" in docs/model-pipeline.md.
- A mesh drawn for the first time while memory is short no longer stops the game. Its per-package bounding boxes are built the first time its vertex buffer is drawn - for every new body, prop or particle buffer - and that build could only throw. The cache now checks that the heap has room first; when it has not, the mesh is skipped that frame and asked for again the next. See docs/model-pipeline.md.
- An animated character made while memory is short no longer stops the game. `SkelInstance::create` first checks that the heap has room for everything the instance will take - for a model's first instance also its skinning data and the temporary table that prepares it - and answers null when it has not. The generated game then plays the object on without a body (nothing is drawn, and its bones read false) and asks again every frame until there is room; this covers a character spawned or joining mid-game and an object streamed back in. See docs/animated-models.md.
- The static pipeline's caches no longer stop the game when the heap is full. The baked VIF stream cache and the retained command cache used to take every block while a game ran with a throwing `new`, so a heap with no room left - or too cut up to hold one block - ended the game. Each block is now taken only if there is room, and a bag that cannot be cached draws the ordinary way that frame and asks again the next; nothing is replayed from memory that was not had. See "When memory is short" in docs/baked-vif-stream.md and docs/retained-static-commands.md.
- Unloading a texture or a song no longer frees memory the wrong way. A texture's pixels and palette, the audio thread's stack and a streamed song's chunk come from `memalign` but were released with `delete[]`, which is undefined behaviour and can corrupt the heap; they are released with `free` now. A song also frees the stage ring it used to leak, and a raytraced mirror's texture is allocated with `memalign` like every other texture.
- **An opt-in memory manager for the EE.** Set `TYRA_MEMORY_MANAGER := 1` in your game's make and every `malloc`, `free` and `new` in the link - the engine, the game, libstdc++ and ps2sdk - goes through the engine's manager, which charges each allocation to a budget (`System`, `Renderer`, `Skinning`, `BakedStreams`, `Audio`, `Level` and your own) and can give a budget a capped region of its own. A full budget stops the game with a `[MEM] FAIL` line that names it, followed by a table of every budget's use and peak, instead of a black screen. Render budgets refuse instead: an allocation in one returns null (a throwing `new` still stops the game), so code that checks can draw something cheaper, or nothing, that frame and ask again the next; every refusal is counted, and a shipping build can turn its log lines off (`Settings::refusalLog`). The manager also brings fixed pools, frame and load scratch memory, `Ptr<T>` handles into a heap that is defragmented a little every frame, and a telemetry block a memory monitor can read while the game runs. `TYRA_MEMORY_CHECKS := 1` adds integrity checks for development builds. Without the switch nothing changes: the engine builds and runs exactly as before. See docs/memory-manager.md.
- Loading another level no longer runs out of memory after a busy scene. The previous scene's baked meshes stayed in memory until they expired 250 frames later, and a load runs no frames, so a level loaded straight after a crowded scene had several megabytes less to work with and could fail to allocate a texture. A scene load now releases the previous scene's cached static geometry first, and with it the bounding boxes cached for its meshes, which could otherwise be mistaken for a new mesh's boxes when its vertices landed at a freed address.
- A scene without a running day/night clock no longer recolours its sky dome on every frame. The dome was rewritten with the same colours on every render pass (twice a frame in split screen), which made the static pipeline bake the dome again each time. It is now recoloured only when its colours change, and a scene without a clock no longer picks up the previous scene's zenith colour.
- Animated characters no longer cut the EE heap into holes while they move. Each time a skinned body was re-posed, its baked VIF stream was copied into a newly allocated block and the old block freed two frames later, so a crowd of 22 fighters allocated and freed about 22 blocks of tens of kilobytes every frame, which fragmented the heap until large allocations failed. A body now keeps a second block and writes its new pose there, alternating between the two, once no frame still being drawn reads it. Its one extra block is counted in the baked-stream budget, so the budget now shows what the cache really holds.
- **Object scripts take parameters.** An attached script can carry named values you set per object in **Properties > Scripts**: press **+ param**, give it a name, a kind (`int`, `float`, `bool` or `string`) and a value, and read it in C++ with `param<int>("team")` (or `paramFloat`, `paramBool`, `paramString`, `hasParam`). Two spawn points are now one class with different numbers, instead of numbers smuggled through an object's scale or colour. A script without parameters is saved exactly as before (`"scripts": ["Spinner"]`); one with parameters is saved as `{ "name": "SpawnPoint", "params": { "team": 1 } }`. Projects are saved as format 123, which an older editor refuses instead of silently dropping the parameters. See docs/object-scripts.md.
- **Object scripts run in a defined order.** The object-script driver used to run wherever the link order put it among the global scripts. It now runs after every global script left at the default order (the flow graphs, the engine's directors and your own `TYRA_SCRIPT` classes), every frame; a global script can set `scriptOrder` in its constructor to run before or after it. An object-script class can declare `static constexpr int kScriptOrder = -100;` to start, tick and be destroyed before (negative) or after (positive) the others, and instances of the same order keep attachment order, which is what every script did before.
- **Start-only markers cost nothing per frame.** A class derived from `MarkerScript` (or with `static constexpr bool kStartOnly = true;`) is constructed and gets `onStart` once and is never ticked: no `onUpdate`, no `onUsed`, no per-frame loop to visit it. It is the shape for spawn points, capture points and waypoints that read their parameters and register themselves. They start as the scene loads (a new `Script::sceneLoaded` hook, called at the end of `loadScene`, before any script's `init` or `update`), so the game's own code reads what they registered from its first frame on the scene.
- **Object scripts live in static storage and get `onDestroy`.** The code generator sizes each class's storage from the attachments (as many instances as the busiest scene attaches) and constructs the instances in place, so attaching a script no longer allocates anything and a scene load allocates nothing. A new `onDestroy(ScriptContext&)` hook runs for every instance when its scene is left or reloaded, before the destructors. A script on an inactive object (its streaming layer is out of memory) is no longer ticked. If you took ownership of `inc/scripts/script.hpp`, copy the new definitions from a project created by this editor.
- A game can set the memory the baked-stream cache may use while it runs. `StaPipCore::setBakedBudgetBytes` changes the limit (it was fixed at 4 MB when the engine was built), `getBakedBudgetBytes`, `getBakedBytes` and `getBakedGraveyardBytes` read it back with what the cache holds and what is waiting to be freed. Lowering the limit frees the least recently used streams over the next frames, a few per frame, and a stream that no longer fits is rebuilt every frame instead of cached.
- A game built from a different TyraX checkout no longer boots with stale objects. Each checkout builds its own copy of the engine, and the game's objects kept pointing at the copy they were first built against, so after switching checkouts - or launching the editor through a path spelled with different capitals on Windows - make kept the old objects and linked them against the other engine library, and the game could halt at boot inside engine code. The game's objects now record which engine copy they were built against and are rebuilt when it changes. A game built before this update rebuilds its objects once. On Windows one checkout now keeps one engine copy however its path is capitalised, so switching launchers no longer rebuilds the engine and the game (the first build after the update rebuilds them once). See "Incremental builds" in docs/native-toolchain.md.
- **`.tmdl` 5: static models are stored compact.** A model's meshes are written quantized in one box per model (positions on a power-of-two grid, normals x 127, UVs on a fixed-point grid chosen per mesh), and older `.tmdl` files are converted at load, so tracked models need no re-export. The engine keeps both the compact copies and the float copies for now; the generated game moves to the compact form in a later step. See docs/model-pipeline.md, "The compact `.tmdl` (version 5)".
- **`.tskl` 3: animated models are stored compact.** A skinned model's meshes are quantized in one box per model, the way `.tmdl` 5 stores static ones, so the model's own mesh costs 22 bytes a vertex in memory instead of 40 (the float bind data the skinning builds from it is unchanged). Older `.tskl` files still load and are converted at load. See docs/animated-models.md, "The `.tskl` file (version 3)".
- **The compact vertex format is the static pipeline's default on this branch** (`docs/compact-vertex-format.md`). A static vertex is stored in 16-bit fixed point, 8-bit where that is exact, laid out the way the VIF unpacks it: a textured, coloured vertex is 16 bytes instead of 48, so EE RAM and the DMA carry about a third of the bytes. In a 24-fighter split-screen match the baked-stream cache peaks at 1 678 KB instead of 5 420 KB, with nothing refused. The packing of re-posed bodies costs about 5 ms a frame on the EE in that match, so this branch is held back from dev-local until that cost is worked off.
- Texture coordinates carry a Q component, so a projective texture (a lamp's or a decal's) works with the compact format. A textured vertex is 2 bytes larger for it. A package wider than 16 repeats is no longer clamped: it is drawn at a coarser texture scale (lower precision), and the bake warns about it.
- Project VU looks: the object-space stages (`ObjectSpace`) see the model's coordinates in grid steps, not metres. A displacement written in metres must be divided by the bag's step (`docs/vu-authoring.md`).
- `tyrax-editor --vu-emit-paint <dir>` writes the paint programs of the VU framework, so a paint look can be inspected or built outside the editor (`docs/vu-framework.md`).
- The VIF-hash gate reads FLG (bit 15, add TOPS) to tell geometry from uniforms, so a unpack's double buffer no longer counts as a uniform.

- The Debugger's VU1 capture view and `--dump-vucap` now decode a chain the way VIF1 reads it: the VIFcodes inside a payload - a baked stream, an inline packet - are listed and their unpacks shown, including the STROW, STCOL, STMASK and STMOD that set how an unpack lands, while NOP padding is left out. `--vu-replay` now writes what an unpack really puts in VU memory for every format - 8 and 16-bit data widened with its sign, masked lanes from the ROW and COL registers, write-protected lanes left alone - where it used to copy only 32-bit data correctly. See "Compact input" in docs/vu-framework.md.
